## Summary

Light Show’s setup chrome is a dark theme with generally strong text contrast and some solid Phone Polish patterns (viewport-fit, safe-area on setup + show chrome, touch-action, tap-to-play `aria-live` prompt, lyric dark scrim). Show-mode accessibility is weaker: canvas lyrics and flashes are artistic-first, with **no `prefers-reduced-motion`**, **no photosensitivity / flash-cap control**, and lyric “LARGE” sizes measured in **canvas/device pixels** (full-quality phone CSS-equivalent often ~20–34px). HUD/status outside `#show-prompt` lack live-region semantics; most controls miss 44×44 floors and `:focus-visible`. Head-movie look (full white-outs, kick/snare flashes, camera shake) intentionally conflicts with calm readability and seizure-safe motion.

## Suggested fix list (recommendations only — do not implement)

### P0 — safety / blockers
1. **Respect `prefers-reduced-motion`:** reduce/disable camera shake, sparklines thrash, LED band animation; soften or disable full `whiteOut` / rapid kick–snare flashes; prefer slow fades.  
2. **Add explicit “Less flash” / “Photosensitive safe” control** (separate from artistic Intensity): hard-cap white-out alpha, raise flash cooldowns (e.g. ≥1s, prefer ≤3 flashes/s), disable snare/kick full-white paths in `renderer.js`.  
3. **Unify flash triggering** so renderer kick/snare cannot bypass director/variation safety caps.

### P1 — high
4. **DPR-aware lyric CSS-px floors** (e.g. min ~28–32 CSS px body, ~36–40 chorus) via `fontSize = max(floorCss * dprEff, …)` (or draw in CSS px space). Revisit comments that state device-px sizes as “on phone.”  
5. **`aria-live="polite"`** (or `role="status"`) on `#status-line` and `#song-card-status`; consider `aria-busy` while Generating.  
6. **Tap targets ≥44×44** for overlay Exit/Fullscreen and style chips (min-height/min-width or padding); keep Phone Polish always-reachable chrome.  
7. **Canvas safe margins** for lyric block and intro theme (`safe-area-inset-top/bottom` via JS or padded draw rect).

### P2 — medium
8. **`:focus-visible` outlines** for buttons and `input[type=text]` (match textarea/select accent).  
9. **`aria-pressed`** on `[data-style]` toggles; optional `aria-label` on icon-only future controls.  
10. **HUD:** larger type or higher-contrast plate when visible; optional “keep HUD on” for debugging vs audience mode.  
11. **Document** Intensity ≠ flash-safety in README / setup hint; point Extreme at photosensitive risk.  
12. **Refresh RELEASE/QA known-limits** — setup safe-area is fixed in current CSS; overlay hide is 8s not 3.5s.

### P3 — low
13. User lyric size preference; respect OS text scaling where feasible.  
14. Reduce overlay dim-only contrast issue (e.g. text-shadow / scrim behind Exit).  
15. Checkbox hit-area padding.
